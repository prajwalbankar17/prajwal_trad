# Database Schema

PostgreSQL 16. **56 tables** plus 15 candle partitions. Generated by Alembic;
`alembic upgrade head` is the only supported way to create or change it.

## Conventions

- UUID primary keys on entity tables; composite natural keys on candle tables.
- `created_at` / `updated_at` with server defaults on entity tables.
- Explicit constraint naming (`app/db/base.py`) so autogenerated migrations are
  readable and stable.
- Money as `NUMERIC`, never float. Prices `NUMERIC(14,4)`, P&L `NUMERIC(18,2)`.
- JSONB for genuinely variable shapes (strategy parameters, condition
  breakdowns, charge details) — not as a way to avoid designing columns.

## A. Instruments

| Table | Purpose |
|---|---|
| `instruments` | The universe. Equity today; `expiry`, `strike`, `option_type`, `underlying_id` are present and unused so the F&O engine needs no schema rewrite. |
| `exchanges` | NSE, BSE, NFO, BFO. |
| `sectors` | Sector classification, used by the sector-exposure limit. |
| `symbol_mappings` | External symbol → instrument. Symbols get renamed; this keeps history attached to the right company. Unique on `(source, source_symbol)`. |
| `corporate_actions` | Splits, bonuses, dividends with `adjustment_factor` and `is_applied_to_history`. |
| `market_holidays` | Exchange calendar. The code prefers these rows over the seeded list. |
| `watchlists`, `watchlist_items` | User groupings. |

Key indexes: `(exchange, tradingsymbol)` unique, `(tradingsymbol, is_active)`,
`sector_id`, `segment`, `instrument_token`.

## B. Market data

| Table | Purpose |
|---|---|
| `intraday_candles` | **Partitioned**, `PARTITION BY RANGE (ts)`, yearly 2018–2031 + DEFAULT. PK `(ts, instrument_id, timeframe)`. |
| `daily_candles` | Daily/weekly/monthly. PK `(instrument_id, timeframe, ts)`. Carries `adjusted_close`. |
| `data_sources` | Provenance. Every candle references one. `kind` distinguishes `HISTORICAL_IMPORT`, `BROKER_HISTORICAL`, `BROKER_LIVE`, `DELAYED`, `MOCK`. |
| `data_import_jobs` | Resumable import state. `cursor` JSONB holds the symbol index and last timestamp. |
| `data_import_failures` | Rejected rows by reason, with a sample. |
| `data_quality_reports` | Coverage snapshots. |
| `data_availability` | Fast "can I backtest this?" lookup. Unique on `(instrument_id, timeframe)`. |
| `live_ticks` | Opt-in tick recording only. Not used by default. |
| `market_status_log` | Feed connection history. |

### Why candles are split this way

Storing every timeframe would mean 10× the rows with no query benefit, and a
guaranteed drift between the stored 15m candle and the one derived from 1m.
1m is the source of truth; everything between 3m and 1h is resampled on read.
Daily and above live separately because a true daily OHLC includes pre-open and
auction prints the minute series does not carry.

Partition management: `alembic/versions/0002_intraday_partitions.py` creates
them. Add future years before they are needed; the DEFAULT partition catches
anything unexpected rather than failing an import mid-run.

## C. Strategies

| Table | Purpose |
|---|---|
| `strategies` | Catalogue. `code` resolves to a class in the registry. |
| `strategy_versions` | Frozen parameter sets, so an old backtest stays explainable. |
| `strategy_configs` | A runnable instance: parameters, timeframe, universe, exits, session window. |
| `strategy_combinations`, `strategy_combination_legs` | 2–5 legs with weight, mandatory flag and role. |
| `strategy_execution_logs` | One row per evaluation pass, with the full condition breakdown. This is what makes a *missing* signal explainable. |
| `trading_module_states` | Per-module Active/Inactive plus `monitor_open_positions`. |

## D. Signals

| Table | Purpose |
|---|---|
| `trading_signals` | Proposals. Unique on `dedupe_key` — one signal per strategy/instrument/timeframe/candle unless the config allows repeats. Carries `conditions`, `risk_validation`, `data_source` and `data_age_seconds`. |
| `signal_history` | Every state transition, never overwritten. |

States: `GENERATED → VALIDATED | REJECTED → PAPER_EXECUTED | EXPIRED | CANCELLED`.

## E. Trading

| Table | Purpose |
|---|---|
| `orders` | Simulated orders. **`CHECK (execution_mode = 'PAPER')`**. |
| `positions` | Open and closed positions. **`CHECK (execution_mode = 'PAPER')`**. Gross, charges and net stored separately, plus MAE/MFE. |
| `trade_executions` | Individual fills with requested price, actual price and slippage. |
| `exit_records` | Why each (partial) exit happened, with its own P&L. |

The CHECK constraints are the last line of defence: even a code bug cannot
record a live order.

## F. Risk

| Table | Purpose |
|---|---|
| `risk_profiles` | Capital and ten limits, plus `assumed_leverage` and the kill switch. |
| `daily_risk_states` | Per profile per day. In PostgreSQL, not only Redis, so it survives a restart. |
| `risk_limit_breaches` | Every block, with the limit and actual value. |
| `exposure_records` | Exposure snapshots by sector and instrument. |

## G. Backtesting

| Table | Purpose |
|---|---|
| `backtest_jobs` | Configuration, progress, `data_coverage`, `warnings`. |
| `backtest_results` | One row per scope: OVERALL, per instrument, per strategy, per window (IN_SAMPLE / OUT_OF_SAMPLE). Holds `overfitting_flags`. |
| `backtest_trades` | Trade-by-trade. Kept apart from `positions` so research volume never slows the trading tables. |
| `backtest_configurations` | Saved setups. |

## H. Portfolio

`portfolios`, `holdings`, `portfolio_snapshots` (the equity-curve series).

## I. AI

| Table | Purpose |
|---|---|
| `ai_prompt_versions` | Versioned prompts. |
| `ai_analysis` | Input context, output, relations to signal/strategy/backtest. |
| `ai_usage_logs` | Tokens, estimated cost, latency, success — recorded on failure too. |
| `ai_recommendations` | Explicitly labelled hypotheses, with a review workflow. |

## J. System

| Table | Purpose |
|---|---|
| `users`, `roles`, `permissions`, `role_permissions`, `user_roles` | RBAC. Permissions are rows, so a new role needs no deployment. |
| `user_sessions` | Refresh-token sessions by `jti`, revocable. |
| `audit_logs` | Append-only. No route updates or deletes these. |
| `notifications`, `notification_preferences` | With `dedupe_key` so an alert is never sent twice. |
| `system_settings` | Non-secret settings, with an `is_sensitive` flag that redacts on read. |
| `broker_connections` | **Metadata only.** `has_credentials` boolean; no token, secret or password is ever stored. |

## Performance notes

- Composite indexes match the actual access patterns:
  `(instrument_id, timeframe, ts)` for candles, `(state, generated_at)` for
  signals, `(status, entry_time)` for positions.
- Imports use multi-row `INSERT ... ON CONFLICT DO NOTHING`, never row-by-row.
- `pool_pre_ping` and `pool_recycle=1800` so a VPS network blip does not
  produce stale-connection errors.
- Data-quality queries use single grouped aggregates rather than per-day
  queries — at 3,000 instruments the difference is hours.
- N+1 avoided with `lazy="selectin"` on role→permission and watchlist→items.
